# imp1sh.ansible_managemynetwork.ansible_syncthing

Installs and configures [Syncthing](https://syncthing.net/) file synchronisation per-user via the REST API. Handles device pairing and folder sharing across hosts in a single Ansible play — no manual device-ID exchange needed.

## Architecture

| Phase | What happens |
|-------|--------------|
| **1. Install** | Installs `syncthing` package via `ansible_packages` (Fedora: official repos, Debian: apt repo) |
| **2. Bootstrap** | Per-user: `syncthing generate` creates `cert.pem` + `config.xml`, reads the auto-generated API key, copies TLS cert/key if enabled, starts `syncthing@<user>` systemd service |
| **3. Firewall** | Opens sync (TCP 22000), discovery (UDP 21027), and GUI ports via firewalld (Fedora) or ufw (Debian) |
| **4. Collect** | Queries `GET /rest/system/status` on each host to obtain the device ID (`myID` derived from `cert.pem`), stored as `syncthing_device_ids[username]` fact |
| **5. Devices** | Adds remote devices via `POST /rest/config/devices` with the collected device IDs |
| **6. Folders** | Adds shared folders via `POST /rest/config/folders` with the full device list (local + remote) |

All REST API calls authenticate via the `X-API-Key` header. The API key is auto-generated by syncthing on first boot and read from `config.xml`.

## Variables

### Core

| Variable | Default | Description |
|----------|---------|-------------|
| `syncthing_users` | `[]` | List of user dicts (see below) |
| `syncthing_folders` | `[]` | Global default folder list (used when user omits `folders`) |
| `syncthing_folder_overrides` | `{}` | Per-host path overrides keyed by folder ID |
| `syncthing_gui_address` | `127.0.0.1:8384` | GUI/API listen address |
| `syncthing_gui_tls` | `false` | Serve GUI over HTTPS |
| `syncthing_gui_cert` | cacert default path | TLS cert PEM path (Fedora cacert layout) |
| `syncthing_gui_key` | cacert default path | TLS key PEM path (Fedora cacert layout) |
| `syncthing_gui_user` | `""` | GUI authentication username (empty = no auth) |
| `syncthing_gui_password` | `""` | GUI authentication password (vault-encrypt!) |
| `syncthing_api_key` | `""` | REST API key (empty = auto-generated by syncthing) |
| `syncthing_configure` | `true` | Skip device/folder config if false (install only) |
| `syncthing_firewall` | `true` | Open firewall ports for sync + GUI |
| `syncthing_sync_port` | `22000` | TCP port for sync protocol |
| `syncthing_discovery_port` | `21027` | UDP port for local discovery |
| `syncthing_linger` | `true` | Enable systemd linger so syncthing runs without login |
| `syncthing_teardown` | `""` | Teardown mode: `""`, `"config"`, or `"full"` |
| `syncthing_folders_absent` | `[]` | Folders to remove during teardown (by ID) |
| `syncthing_options` | `{}` | Global syncthing options dict (PATCHed via REST API) |
| `syncthing_device_defaults` | _(see below)_ | Defaults applied to every remote device |
| `syncthing_device_address_mode` | `dynamic` | `dynamic` or `static` |

### syncthing_users

Each user gets a separate `syncthing@<user>` systemd instance with its own config, device ID, and daemon. All settings can be global (shared defaults) or per-user (keys on the user dict).

#### Per-user overrides

All of the following can be set globally (top-level vars) or per-user (keys on the user dict). Per-user values override globals.

| Key | Global var | Description |
|-----|------------|-------------|
| `gui_address` | `syncthing_gui_address` | GUI/API listen address |
| `gui_tls` | `syncthing_gui_tls` | Enable HTTPS for GUI |
| `gui_cert` | `syncthing_gui_cert` | Path to TLS cert PEM |
| `gui_key` | `syncthing_gui_key` | Path to TLS key PEM |
| `gui_user` | `syncthing_gui_user` | GUI authentication username |
| `gui_password` | `syncthing_gui_password` | GUI authentication password (vault-encrypt!) |
| `api_key` | `syncthing_api_key` | REST API key |
| `linger` | `syncthing_linger` | Enable systemd linger |
| `options` | `syncthing_options` | Global syncthing options dict |
| `folders` | `syncthing_folders` | List of shared folders |
| `folders_absent` | `syncthing_folders_absent` | Folders to remove (teardown) |
| `teardown` | `syncthing_teardown` | Teardown level for this user only (`""`, `"config"`, `"full"`) |
| `hosts` | _(all hosts in play)_ | List of inventory hostnames in this user's sync cluster |
| `firewall` | `syncthing_firewall` | Open firewall ports for this user |
| `sync_port` | `syncthing_sync_port` | TCP port for sync protocol (must be unique per user on a host) |
| `discovery_port` | `syncthing_discovery_port` | UDP port for local discovery (must be unique per user on a host) |

```yaml
# Single user with global settings
syncthing_users:
  - username: jochen

# Explicit host list — only these hosts participate in jochen's sync
syncthing_users:
  - username: jochen
    hosts:
      - framework.t.libcom.de
      - pc-gast.t.libcom.de
    folders:
      - id: "jochensync"
        path: "/home/jochen/jochensync"
    gui_tls: true
    gui_address: "[::]:8384"
    gui_user: "jochen"
    gui_password: !vault |
      $ANSIBLE_VAULT;1.1;AES256
      ...

# Multiple users with different sync clusters
syncthing_users:
  - username: jochen
    hosts:
      - framework.t.libcom.de
      - pc-gast.t.libcom.de
    folders:
      - id: "jochensync"
        path: "/home/jochen/jochensync"
  - username: alice
    hosts:
      - framework.t.libcom.de
      - e14.t.libcom.de
    gui_address: "127.0.0.1:8385"
    sync_port: 22001
    discovery_port: 21028
    folders:
      - id: "alice-sync"
        path: "/home/alice/alicesync"
```

When a per-user key is omitted, the global default is used. When `hosts` is omitted, all hosts in the ansible play participate.

### syncthing_folders

| Key | Required | Default | Description |
|-----|----------|---------|-------------|
| `id` | yes | — | Unique folder ID (must match on all devices) |
| `path` | yes | — | Local filesystem path |
| `label` | no | `id` | Human-readable name |
| `type` | no | `sendreceive` | `sendreceive`, `sendonly`, `receiveonly` |
| `rescan_interval` | no | `3600` | Rescan interval in seconds |
| `fs_watcher` | no | `true` | Enable filesystem watcher |
| `fs_watcher_delay` | no | `10` | Seconds to accumulate changes before scan |
| `paused` | no | `false` | Pause the folder |
| `ignore_perms` | no | `false` | Ignore permission bits |

```yaml
folders:
  - id: "shared-documents"
    label: "Shared Documents"
    path: "/home/jochen/Documents"
  - id: "photos"
    path: "/home/jochen/Bilder"
    type: "sendreceive"
```

### Per-host path overrides

```yaml
# host_vars/framework.t.libcom.de.yml
syncthing_folder_overrides:
  shared-documents: /data/sync/documents
```

### Global options

Keys match the Syncthing config JSON field names (see `GET /rest/config/options`):

```yaml
syncthing_options:
  globalAnnounceEnabled: true
  localAnnounceEnabled: true
  relaysEnabled: true
  natEnabled: true
  startBrowser: false
```

### Device defaults

Applied to every remote device added via REST API:

```yaml
syncthing_device_defaults:
  compression: "metadata"
  introducer: false
  paused: false
  autoAcceptFolders: false
```

### Device addressing

| Mode | Description |
|------|-------------|
| `dynamic` (default) | Use local/global discovery — no static addresses needed |
| `static` | Use `tcp://<inventory_hostname>:22000` — requires reachable IPs |

```yaml
syncthing_device_address_mode: "dynamic"
```

## GUI TLS

Serve the web GUI over HTTPS using a CA-signed certificate. Typically paired with `ansible_cacert` which deploys per-host certs to `/etc/pki/tls/`.

```yaml
syncthing_gui_tls: true
# Cert/key paths default to the ansible_cacert Fedora layout:
# syncthing_gui_cert: "/etc/pki/tls/certs/main_jochenit_{{ inventory_hostname }}_certificate.pem"
# syncthing_gui_key: "/etc/pki/tls/private/main_jochenit_{{ inventory_hostname }}_privatekey.pem"
```

The role copies the cert/key into `~/.local/state/syncthing/` as `https-cert.pem` / `https-key.pem` and patches the GUI config to enforce TLS. A restart is triggered automatically.

## GUI authentication

Protect the web GUI with a username and password. The password is hashed via bcrypt by syncthing's REST API on write — pass plaintext, not a pre-hashed value.

```yaml
syncthing_gui_user: "jochen"
syncthing_gui_password: !vault |
  $ANSIBLE_VAULT;1.1;AES256
  ...
```

Or per-user:

```yaml
syncthing_users:
  - username: jochen
    gui_user: "jochen"
    gui_password: !vault |
      $ANSIBLE_VAULT;1.1;ES256
      ...
```

When both `gui_user` and `gui_password` are empty (default), no authentication is configured.

## Firewall

The role opens three ports per user via firewalld (Fedora/RHEL) or ufw (Debian/Ubuntu):

| Port | Protocol | Purpose |
|------|----------|---------|
| `sync_port` (22000) | TCP | Sync protocol between devices |
| `discovery_port` (21027) | UDP | Local network discovery |
| GUI port (from `gui_address`) | TCP | Web GUI / REST API (only opened if not localhost-bound) |

Ports are per-user — each `syncthing@<user>` instance on a shared host must use unique ports:

```yaml
syncthing_users:
  - username: jochen
    gui_address: "[::]:8384"
    sync_port: 22000
    discovery_port: 21027
  - username: alice
    gui_address: "[::]:8385"
    sync_port: 22001
    discovery_port: 21028
```

Set `syncthing_firewall: false` (or per-user `firewall: false`) to skip firewall management entirely. During teardown, the same ports are closed.

## Usage

In `group_vars/os_desktop_fedora.yml`:

```yaml
syncthing_users:
  - username: jochen
    gui_tls: true
    gui_address: "[::]:8384"
    gui_user: "jochen"
    gui_password: !vault |
      $ANSIBLE_VAULT;1.1;AES256
      ...
    options:
      startBrowser: false
    folders:
      - id: "jochensync"
        label: "Jochensync"
        path: "/home/jochen/jochensync"
        fs_watcher_delay: 1
```

Playbook (target a broad group — the `hosts` key on each user dict decides participation):

```yaml
- hosts: os_desktop_fedora
  become: true
  roles:
    - imp1sh.ansible_managemynetwork.ansible_syncthing
```

All hosts in the play automatically discover each other's device IDs and pair. Folders are shared between all hosts that have the same user configured. Adding a new host is just adding it to the `hosts:` line.

## Host selection

Each user dict can specify a `hosts` list naming the inventory hosts that participate in that user's sync cluster. The playbook should target a superset (e.g. `os_desktop_fedora`); the role skips hosts not listed in any user's `hosts` list.

```yaml
syncthing_users:
  - username: jochen
    hosts:
      - framework.t.libcom.de
      - pc-gast.t.libcom.de
```

- Hosts in the play but not in `hosts` are skipped for that user (no install, no bootstrap, no pairing)
- Device pairing and folder sharing are limited to hosts in the same `hosts` list
- When `hosts` is omitted, all hosts in the play participate (backward compatible)
- Different users can have overlapping or disjoint host lists — jochen syncs across framework+pc-gast, alice across framework+e14

## How device pairing works

1. Each host boots syncthing, generating a certificate and device ID
2. The role queries `GET /rest/system/status` → `myID` on each host
3. Device IDs are stored in a `syncthing_device_ids` dict fact keyed by username
4. Each host reads the other hosts' device IDs from `hostvars` and adds them via `POST /rest/config/devices`
5. Each host shares folders with the full device list (local + remote) via `POST /rest/config/folders`

No manual device-ID copy/paste. Adding a new host to the play group automatically extends the cluster.

## REST API endpoints used

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/rest/config/gui` | `PATCH` | Set GUI address, TLS, API key, auth |
| `/rest/system/status` | `GET` | Retrieve local device ID (`myID`) |
| `/rest/config/devices` | `GET` / `POST` | List / add remote devices |
| `/rest/config/devices/<id>` | `DELETE` | Remove a remote device (teardown) |
| `/rest/config/folders` | `GET` / `POST` | List / add shared folders |
| `/rest/config/folders/<id>` | `DELETE` | Remove a folder config (teardown) |
| `/rest/config/options` | `PATCH` | Apply global options |

API docs: https://docs.syncthing.net/dev/rest

## Teardown

Remove syncthing configuration and optionally all components. **Synced data on disk is never deleted** — only syncthing's own config, database, and (in `full` mode) the package itself.

### Global teardown

Applies to ALL users in `syncthing_users`:

| Level | What happens |
|-------|-------------|
| `""` (default) | Normal operation — no teardown |
| `"config"` | Deletes all folders and remote devices via REST API `DELETE`, stops and disables the systemd service, closes firewall ports. Synced files on disk are left intact. |
| `"full"` | Everything in `"config"` PLUS removes the syncthing config directory (`~/.local/state/syncthing/`), uninstalls the package, and disables lingering. Synced files on disk are still left intact. |

```yaml
# Remove all folder/device config, stop service, close ports, leave data intact
syncthing_teardown: "config"

# Full removal: config dir + package + lingering, data still intact
syncthing_teardown: "full"
```

### Per-user teardown

Tear down one user's sync instance while leaving others running. Set `teardown` on the user dict — overrides the global `syncthing_teardown` for that user only.

```yaml
syncthing_users:
  - username: jochen
    # jochen stays running
  - username: alice
    teardown: "config"   # remove alice's folders + devices, stop her service
  - username: bob
    teardown: "full"     # full removal for bob: config dir + package + linger
```

Users without a `teardown` key follow the global `syncthing_teardown` setting. When the global is empty and only specific users have `teardown`, only those users are affected.

To remove only specific folders while keeping others:

```yaml
syncthing_teardown: "config"
syncthing_folders_absent:
  - "jochensync"
  - "old-folder-id"
```

Per-user folder removal — set `folders_absent` on the user dict:

```yaml
syncthing_teardown: "config"
syncthing_users:
  - username: jochen
    folders_absent:
      - "jochensync"
  - username: alice
    # alice keeps all her folders
```

When `folders_absent` is empty (default) and teardown is enabled, **all** folders are removed for that user.

## Notes

- Syncthing uses `$HOME/.local/state/syncthing/` (XDG State Home) for config and certs since v1.27. Older installations may use `~/.config/syncthing/`.
- The systemd service is `syncthing@<username>` (system-managed per-user instance).
- Lingering is enabled by default so syncthing runs even when the user hasn't logged in.
- The role is non-destructive: existing configs are not overwritten. `syncthing generate` only runs when `config.xml` doesn't exist.
- GUI auth passwords are hashed via bcrypt by the REST API — pass plaintext, not a pre-hashed value.
